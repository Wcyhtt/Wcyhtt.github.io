行为克隆，在哪里失效

在 RoboSuite 的 Lift 任务上，用脚本专家采集演示、训练一个纯 MLP 策略，然后做两件事：看演示数量够不够，以及把方块挪出训练分布之后还剩多少成功率。全部在 CPU 上完成。

实验设置

仿真环境RoboSuite 1.5 / MuJoCo 3.3
任务 / 机器人Lift / Franka Panda
观测11 维本体状态
演示来源手写状态机专家
成功判定方块高出桌面 8 cm
评估强度每配置 15–20 回合

动作 7 维（三维位移 + 三维旋转 + 夹爪）。策略是一个两层 128 隐单元的 MLP：前 6 维做回归（MSE），夹爪单独做二分类（BCE）—— 混在一起回归会让夹爪在 0 附近抖动。

10 条演示就到 100%，说明这个任务对行为克隆没有难度：观测里直接给了方块坐标（相当于开卷），专家是确定性的，状态到动作的映射非常规整。这只能说明任务简单，不能说明方法强。

第二组：把方块挪出训练分布

训练时方块落在桌子中部；测试时不重新训练，只把方块整体沿对角线挪开一段距离。

读这张图要注意什么

两个条件唯一的差别是方块位置，环境物理、机械臂、控制器完全一样。

行为克隆在 5 cm 内还稳，10 cm 开始掉（86.7%），15 cm 崩到 33.3%；脚本专家在所有偏移下都是 100%。

所以下降的原因不可能是"够不着"——同一状态下专家能完成。只能是策略没在这种状态上学过。

为什么是这样：协变量偏移

行为克隆只学了一件事：在演示覆盖到的状态上，专家会输出什么动作。它没有任何机制知道自己"没学过"。

a_t = π(s_t) ← 只在 s_t ∈ D_demo 上被监督过

一旦环境把智能体推到分布外的状态 sₜ，策略的输出偏差会被环境放大：动作错 → 下一个状态更偏 → 再下一个更远。这就是误差累积（compounding error），偏移足够大时策略会一路偏到不可恢复。

脚本专家不受影响，因为它是闭环的：每一步都重新读一次方块位置再纠偏，误差不会攒起来。这正是"学习策略"和"控制器"的本质差别之一。

所以更准确的说法不是"行为克隆不行"，而是：它的可靠性边界由训练分布决定，而分布外行为没有任何保证。任何只报"成功率 100%"的结论，都必须同时交代测试分布是怎么来的。

证据边界

  • 只有一个任务（Lift）和一个机器人（Panda），不能外推到其他操作任务。
  • "专家"是手写状态机，不是人类遥操作 —— 演示的规整程度远高于真人数据。
  • 观测是本体状态，不是图像。换成相机后结果和失效模式都可能不同。
  • 每配置 15–20 回合，成功率的分辨率只有 5–6.7 个百分点；85% 和 100% 的差异属于这个量级内，不宜过度解读。
  • 偏移是人为平移方块，不等于真实世界的分布漂移（光照、磨损、物体替换等）。

这套实验的目的不是提出新方法，而是把"照着论文跑一遍"落到可复现的流程上：基线、对照、指标定义、边界说明。

复现

Python 3.11 + RoboSuite 1.5.2 + MuJoCo 3.3.7 + PyTorch 2.15（CPU）。整套流程 7 分 38 秒跑完，含 50 条演示采集、4 档训练、两轮基线。

python collect.py --demos 50 --min-lift 0.08 python train_bc.py --data demos_50.npz --out policy.pt python run_shift.py --policy policy_50.pt --episodes 15

踩过的两个坑：RoboSuite 的夹爪动作是 +1 闭合 / -1 张开（写反会看到机械臂攥着拳头往下怼）；自带的成功判定只要抬 4 cm，而方块初始就高 3.2 cm，几乎没有区分度，所以这里统一改成 8 cm。
